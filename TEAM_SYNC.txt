1. EXECUTIVE SUMMARY: WHAT HAS BEEN BUILT & HOW THE BASE CURRENTLY WORKS
--------------------------------------------------------------------------------
RedLab has evolved from initial static concepts into an interactive visual
network attack and defense simulation platform. All legacy cloud/AWS concepts
have been completely removed. The application runs locally, offline, and self-
contained with zero paid cloud dependencies, zero external network calls, and
zero fake buttons.

KEY FEATURES BUILT & OPERATIONAL IN V1.1.1:

1. Top-Level Mode Architecture:
   - "ATTACK STUDIO" (Offensive Mode) vs "DEFEND STUDIO" (Defensive Mode).
   - A single prominent toggle at the top switches modes cleanly.
   - Offense mode unlocks exploit tools, automated attacks, and reconnaissance.
   - Defense mode locks down attack tools and activates ACL remediation, firewall
     configuration, and verification suites.

2. Visual Network Topology Canvas (React Flow):
   - Supports 6 core network devices: PC, Router, Switch, Server, Firewall, External WAN.
   - Custom SVG icons, live status badges, IP/Subnet annotations.
   - Automatic cable reconnection & self-healing edge mechanics.
   - Single source of truth is Zustand (`useEditorStore`).

3. Interactive Linux Attack Terminal (Kali-style bash simulation):
   - Located directly on the bottom simulation drawer under "Terminal".
   - Commands supported:
     * Recon: nmap (SYN stealth port scan), ping (ICMP reachability test)
     * Exploits: hping3 (SYN Flood DoS), hydra (SSH brute force), curl (SQLi)
     * Diagnostics: ip a, ifconfig, route -n, iptables -L -n, netstat, hosts
     * Forensics & Victim View: forensics, ports, screen, victim, monitor
   - When targets are overwhelmed by SYN flood, `ping` accurately reports 100%
     packet loss and socket queue exhaustion.

4. Educational Port Forensics Engine ("Who Closed It & How?"):
   - Solves the fundamental learning gap for networking students.
   - Probes common ports (21/FTP, 22/SSH, 23/Telnet, 80/HTTP, 443/HTTPS, 3306/MySQL, 8080/App).
   - For every port, clearly explains:
     * State: OPEN, CLOSED, or FILTERED.
     * Who Closed/Decided: Target OS Kernel vs Perimeter Firewall ACL vs Daemon.
     * How It Got Closed: TCP RST packet returned vs silent firewall packet drop.
     * Attacker Takeaway: Host presence revealed vs host presence hidden.
     * Defender Advice & Remediation: Exact rules/commands to apply.

5. Simulated Target Victim Monitor Screen:
   - Accessible via the "🖥️ View Target Victim Screen" button or terminal `screen`.
   - Web Server Screen:
     * HTTP 504 Gateway Timeout Outage screen with live ICMP ping test widget.
     * SQL Injection Defacement screen ("HACKED BY REDLAB TEAM") with dumped database table.
     * Healthy online 200 OK enterprise status monitor.
   - Linux Server Screen:
     * Simulated CRT / tty1 terminal showing unauthorized root session compromise,
       `/etc/shadow` credential dump, and active backdoor alert.
   - One-click "Switch to DEFEND MODE to Restore Target" button.

6. Deterministic Defense Verification:
   - Students remediate misconfigurations (e.g., adding firewall drop rules,
     changing default deny actions, enabling SYN cookies).
   - One-click "Verify Defense": runs automated rescan and produces side-by-side
     before/after evidence comparison (e.g. "Vulnerability Remediated: Exploit Blocked").

7. Standalone Desktop Release:
   - Fully packaged Electron + Python PyInstaller bundle for macOS (`RedLab-1.1.1.dmg`).

2. ARCHITECTURAL GUARDRAILS — DO NOT RUIN THE BASE
--------------------------------------------------------------------------------
To any human developer or AI model (Cursor, Claude, Copilot, ChatGPT, Antigravity)
working in feature branches:

RULE 1: ABSOLUTELY NO CLOUD SERVICES OR AWS SDKs.
  RedLab is NOT an AWS security auditor. Do NOT add S3, IAM, CloudTrail, AWS SDKs,
  boto3, or cloud icons. The platform is dedicated to Computer Networking
  (TCP/IP, ICMP, ARP, Subnets, Routers, Switches, Firewalls, Web Servers).

RULE 2: NO FAKE SCANS, NO FAKE BUTTONS, NO HARDCODED RESULTS.
  All network events, port scans, and attack simulations must execute through the
  deterministic backend engine (`app/network_engine/` and `app/security_engine/`).

RULE 3: STRICT DARK CYBERSECURITY AESTHETIC.
  Backgrounds: #0B0D12 (canvas/main), #11151D (sidebar/subpanels), #171C26 (cards).
  Borders: #293140.
  Text: #F3F5F8 (primary), #9BA5B5 (muted/secondary).
  Accents: Red #FF3B4E (exploit/critical), Orange #FF8A4C, Yellow #F5C451,
           Blue #60A5FA (info/links), Emerald #34D399 (secure/defended).
  DO NOT introduce white backgrounds, light mode toggles, or glassmorphism.

RULE 4: ZUSTAND IS THE SINGLE SOURCE OF TRUTH.
  Global canvas nodes, edges, active lab, and selected nodes live in `useEditorStore`.
  Simulation runs and attack responses live in `useSimulationStore`.
  Never duplicate graph topology into local React `useState`.

RULE 5: SYNCHRONIZED SCHEMAS.
  If you modify schemas in `backend/app/schemas/lab.py`, you MUST update
  `frontend/src/types/index.ts` to keep both ends in 100% TypeScript/Pydantic parity.

RULE 6: MANDATORY TEST PASSING BEFORE MERGING.
  Backend: `cd backend && python3 -m pytest tests/ -v` (Must pass all 72 tests).
  Frontend: `cd frontend && npm run build && npm test` (Must pass with 0 errors).
